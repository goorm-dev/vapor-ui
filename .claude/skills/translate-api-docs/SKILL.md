# translate-api-docs

## 사용 시점

`packages/core`의 영어 JSDoc을 `ts-api-extractor`로 뽑은 뒤, 그 설명문을 한국어로 옮긴 결과가 쓸 만한지 확인할 때 사용합니다.

트리거 표현:

- `/translate-api-docs`
- "번역 검증해줘"
- "용어 일관성 확인"
- "번역 빠진 거 없나"

## 파이프라인에서의 위치

번역은 `@vapor-ui/ts-api-extractor` 패키지 안에 있습니다. 추출과 번역이 같은 출력 스키마를 공유하기 때문입니다.

| 명령                                   | 하는 일                                   | LLM                |
| -------------------------------------- | ----------------------------------------- | ------------------ |
| `pnpm api-docs`                        | 추출 → 사전 적용, 사전에 없는 원문만 번역 | 호출함 (로컬 전용) |
| `pnpm api-docs:translate --apply-only` | 사전 적용만. 없는 원문이 있으면 실패      | 호출 안 함 (CI용)  |
| `pnpm api-docs:verify`                 | 사전 내용 검증                            | 호출 안 함         |

번역 결과가 개발자마다 달라지지 않는 것은 도구를 끄기 때문이 아니라 **사전(`translations.ko.json`)이 커밋되기 때문**입니다. 사전이 원문을 덮고 있으면 LLM을 한 번도 부르지 않습니다.

## 검증 방식

`pnpm api-docs:verify`는 사전의 각 항목에 네 가지 규칙을 적용합니다. LLM을 호출하지 않으므로 같은 입력에 항상 같은 결과를 냅니다.

- **빈 번역** — 값이 비었거나 공백뿐
- **코드 스팬 훼손** — 원문의 백틱 스팬(`` `<button>` ``)이 번역문에서 사라지거나 바뀜
- **미번역** — 번역문에 한글이 하나도 없음
- **용어 사전 위반** — `terms.json`의 `avoid` 표기가 번역문에 등장

**번역 누락(커버리지)은 이 명령이 보지 않습니다.** 사전이 추출된 원문을 다 덮는지는 `pnpm api-docs:translate --apply-only`가 검사하고, 거기서 실패하면 검증까지 오지 않습니다. 덕분에 verify는 추출 산출물에 의존하지 않습니다 — 번역이 적용된 한국어 디렉터리를 원문으로 착각하던 문제가 구조적으로 사라집니다.

위반이 없으면 `요약: 위반 0건` 한 줄과 함께 exit 0, 있으면 케이스별 블록을 출력하고 exit 1로 끝냅니다.

스크립트의 stdout을 **있는 그대로** 사용자에게 전달하세요. 요약·재배치·테이블 변환 금지.

## 용어 사전

`scripts/ts-api-extractor/terms.json`이 정본입니다. 번역을 새로 돌릴 때 이 파일의 `terms`와 `sentencePatterns`가 프롬프트에 그대로 들어갑니다.

**등재 기준: 실제 번역에서 갈린 것만 올립니다.** 예방적으로 추가하지 마세요 — 검증기가 `avoid` 표기를 기계적으로 잡기 때문에, 근거 없는 항목은 정당한 번역을 오탐으로 막습니다.

현재 등재된 네 건은 전수 파일럿(고유 원문 321개)에서 실제로 표기가 갈렸던 것들입니다. 예를 들어 `dialog`는 배치 경계에서 "대화 상자" 24건과 "다이얼로그" 18건으로 갈렸습니다.

## 규칙 추가

검증 규칙은 `scripts/ts-api-extractor/src/translate/core/rules.ts`의 배열입니다. 규칙을 늘릴 때는 배열에 항목을 추가하고 테스트(`test/translate-rules.test.ts`)를 붙이면 됩니다 — 실행 쪽은 건드리지 않습니다.

## 한계

- 검사하는 것은 **형식**입니다. 번역이 원문의 뜻을 옳게 옮겼는지는 판정하지 않습니다.
- `avoid` 문자열 포함 여부만 보므로, 정당한 맥락에서 그 표기를 써야 하는 경우에도 위반으로 잡습니다. 그런 사례가 나오면 `terms.json`에서 해당 항목을 빼는 쪽이 맞습니다.
- 사전의 키는 원문과 **정확히 일치**해야 합니다. 공백·줄바꿈이 다르면 다른 원문으로 취급합니다.
