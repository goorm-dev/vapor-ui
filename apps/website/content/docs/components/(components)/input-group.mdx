그룹이 통합하는 시각(테두리·배경 제거, 높이 정렬)을 적용받으려면 입력과 버튼을 각각 `InputGroup.Input`과 `InputGroup.Button`으로 감싸야 합니다. 아이콘 버튼(clear·비밀번호 토글 등)은 compact 크기로 자동 정렬되는 `InputGroup.IconButton`을 쓰면 됩니다. 래퍼 없이 `TextInput`이나 `IconButton` 같은 컨트롤을 그룹 안에 직접 넣으면 그룹이 스타일을 통합하지 않으며, 이때는 각 컨트롤의 시각을 직접 맞춰야 합니다.

### States

그룹이 직접 받는 상태는 `disabled` 하나뿐입니다. `InputGroup.Root`에 주면 안에 있는 `InputGroup.Input`과 버튼이 함께 꺼집니다. 어떤 상태가 그룹 prop이 되는지는 그룹 안 모든 파트에 똑같이 적용되는지로 갈립니다. `disabled`는 입력창도 버튼도 함께 꺼야 하니 여기에 들지만, `readOnly`는 복사 버튼을 살려둬야 하고 `invalid`는 원인이 특정 컨트롤 하나에 있어 들지 않습니다. 그래서 `readOnly`와 `invalid`는 값을 담은 컨트롤에 지정하며, 그룹은 그 상태를 감지해 배경과 테두리에 반영합니다.

`invalid`를 값 컨트롤에 두면 어느 칸이 잘못됐는지가 스크린리더에 전달됩니다. 그룹이 통째로 잘못됐다고 표시하면 테두리만 빨개질 뿐, 사용자는 어디를 고쳐야 할지 알 수 없습니다.

그룹은 하나의 논리적 필드입니다. 그려지는 면이 그룹 표면 하나뿐이라 상태 시각도 그 면에만 나타나므로, 서로 독립적으로 검증되는 값 두 개를 한 그룹에 넣지 않습니다. 값 둘이 동시에 잘못되면 테두리도 하나, 오류 문구도 하나여서 무엇을 고쳐야 하는지 전달할 방법이 없습니다.

같은 이유로 값 컨트롤 일부만 끄거나 읽기전용으로 만들지 않습니다. 값 하나만 읽기전용으로 두면 그룹 전체가 회색이 되는데 나머지 컨트롤은 그대로 조작되어, 보이는 것과 실제 동작이 어긋납니다. 하나의 필드에는 하나의 `disabled`, 하나의 `readOnly`만 둡니다.

그룹 안에 `Select`를 편입할 때 `disabled`와 `readOnly`, `size`는 `Select.Root`에 직접 지정합니다. 편입된 컴포넌트의 Root는 그룹 바깥에 있어 그룹이 상태를 내려보낼 수 없습니다. 그룹이 맞추는 것은 높이 같은 시각뿐이라, `size`를 빠뜨리면 트리거의 값 텍스트와 아이콘만 그룹과 다른 크기로 남습니다. 상태 쪽은 편입된 트리거가 방출하는 값을 그룹이 감지해 배경까지 함께 맞춥니다.

버튼은 `readOnly`를 물려받지 않습니다. 값을 바꾸지 않는 복사·비밀번호 토글 버튼은 읽기전용 필드에서도 눌려야 하기 때문입니다. 값을 지우는 clear 버튼처럼 읽기전용에서 막아야 하는 버튼은 그 버튼에 `disabled`를 직접 지정하세요. 반대로 clear 버튼 하나만 꺼도 그룹 전체가 흐려지지는 않습니다.

`disabled`는 그룹 안의 포인터 입력을 막지만 키보드까지 막지는 못합니다. `render`로 링크처럼 폼 요소가 아닌 것을 넣었다면 그 요소의 키보드 접근은 직접 차단해야 합니다.

### With Field

Field와 결합하면 검증 실패 시 입력에 붙는 `aria-invalid`를 그룹이 감지해 테두리를 danger로 바꿉니다.

그룹 안 컨트롤은 `Field.Label`의 이름을 함께 갖습니다. Field는 필드 하나에 컨트롤 하나를 전제하고 라벨을 붙이므로, 값 컨트롤을 둘 이상 넣으면 보조 컨트롤도 같은 이름으로 낭독됩니다.
