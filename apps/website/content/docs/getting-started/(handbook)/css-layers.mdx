Vapor UI는 모든 컴포넌트 스타일을 [CSS Cascade Layer](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer) 로 감싸 priority 충돌을 예방합니다. 기본 사용 방법과 레이어 순서를 직접 지정하는 방법을 소개합니다.

## 레이어 구성

Vapor UI는 다섯 개의 레이어를 사용합니다. 아래로 갈수록 우선순위가 높습니다.

| 레이어             | 포함 스타일                                          |
| ------------------ | ---------------------------------------------------- |
| `vapor-theme`      | 테마 토큰(`--vapor-color-*` 등)과 라이트/다크 바인딩 |
| `vapor-reset`      | `*`, `html`, `body` 등에 적용되는 전역 reset         |
| `vapor-components` | 각 컴포넌트의 base, variant, recipe 스타일           |
| `composites`       | `@vapor-ui/composites` 컴포넌트 내부 스타일          |
| `vapor-utilities`  | `@vapor-ui/style-macro` 의 `css()` 가 생성한 스타일  |

## 엔트리 구성

| 엔트리                      | 내용                                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `@vapor-ui/core/layers.css` | 레이어 순서 선언만 포함 — `@layer vapor-theme, vapor-reset, vapor-components, composites, vapor-utilities;` 과 동일 |
| `@vapor-ui/core/styles.css` | `@property` 전역 변수 + 테마 토큰 + reset 스타일                                                                    |

두 파일 모두 import 하는 것이 기본이며, 외부 라이브러리와 레이어 순서를 섞어야 하는 경우에만 `layers.css` 를 생략하고 최상위에서 `@layer ...;` 를 직접 선언합니다.

## 기본 사용

애플리케이션 최상위 CSS 파일에 다음 두 줄을 추가합니다.

```css title="global.css"
@import '@vapor-ui/core/layers.css';
@import '@vapor-ui/core/styles.css';
```

`layers.css` 가 먼저 import 되어 레이어 순서를 확정한 뒤, `styles.css` 의 토큰과 reset 이 각 레이어에 올바르게 배치됩니다.

### CSS 진입점은 가장 먼저 import 합니다

브라우저는 레이어 이름이 **처음 등장한 순서**로 레이어를 등록하고, 나중의 `@layer ...;` 선언으로는 이미 등록된 순서를 바꾸지 못합니다. `@vapor-ui/core`, `@vapor-ui/composites` 컴포넌트는 자기 CSS를 함께 불러오므로, 이 컴포넌트를 CSS 진입점보다 먼저 import 하면 레이어가 의도와 다른 순서로 등록됩니다. 예를 들어 `composites` 가 `vapor-utilities` 뒤에 등록되면 `css()` 로 작성한 앱 스타일이 composites 스타일에 집니다.

```tsx title="src/main.tsx"
// ✅ CSS 진입점이 모든 Vapor UI import 보다 먼저
import './styles.css';

import { ThemeProvider } from '@vapor-ui/core';
```

```tsx title="src/main.tsx"
// ❌ 컴포넌트 CSS가 먼저 로드되어 레이어 순서가 어긋남
import { ThemeProvider } from '@vapor-ui/core';

import './styles.css';
```

import 정렬 도구를 쓴다면 side-effect import(`import './styles.css'`)를 재배치하지 않도록 설정합니다.

### `@vapor-ui/style-macro` 를 사용하는 경우

`css()` 매크로로 작성한 스타일은 번들러가 파일마다 방출하지 않고, 프로젝트 전체를 모아 **한 번에 정렬한 뒤** `vapor-utilities` 레이어에 넣습니다. 번들러 플러그인은 `@vapor-ui/core/layers.css` 를 import 하는 CSS 파일을 삽입 지점으로 삼으므로 기본 사용법 그대로면 추가 설정이 없습니다. `layers.css` 를 생략하고 레이어 순서를 직접 선언하는 경우에만 그 CSS 진입점에 `@vapor-utilities;` 를 한 번 직접 적습니다.

```css title="global.css (레이어 순서 직접 선언 시)"
@layer app-base, vapor-theme, vapor-reset, vapor-components, composites, vapor-utilities, app-utilities;
@import '@vapor-ui/core/styles.css';

@vapor-utilities;
```

- `layers.css` import 도, `@vapor-utilities;` 도 없으면 `css()` 스타일이 전혀 방출되지 않습니다.
- `@vapor-utilities;` 는 번들러가 직접 읽는 CSS 진입점에 적습니다. `@import` 된 다른 CSS 파일 안에 두면 인식되지 않습니다.
- 여러 파일에 적으면 전체 유틸리티가 그 수만큼 중복됩니다.
- 정렬 순서(shorthand → longhand → `:hover` 등 pseudo → `@media`)는 파일·청크 순서와 무관하게 고정되므로, 다른 파일에서 전달한 `className` 의 `@media` / `:hover` override 가 항상 base 를 이깁니다.

번들러별 설정은 [`@vapor-ui/style-macro` README](https://github.com/goorm-dev/vapor-ui/tree/main/packages/style-macro) 를 참고하세요.

## 레이어 순서 커스터마이징

외부 CSS 라이브러리(Tailwind, 자체 디자인 시스템 등)와 섞어 쓰면서 특정 레이어를 Vapor UI 위/아래에 두어야 한다면 `layers.css` 를 import 하지 않고 최상위에서 레이어 순서를 직접 선언합니다.

```css title="global.css"
/* 1. 최상위에서 레이어 우선순위 직접 선언 (layers.css 생략) */
@layer app-base, vapor-theme, vapor-reset, app-components, vapor-components, composites, vapor-utilities, app-utilities;

/* 2. Vapor UI 토큰 + reset */
@import '@vapor-ui/core/styles.css';

/* 3. 외부 라이브러리 또는 자체 CSS */
@import 'your-library/base.css' layer(app-base);
@import './app.css';
```

`@layer` 선언이 최초로 등장한 순서가 cascade 우선순위를 결정하므로, 최상위 CSS 파일의 `@layer ...;` 는 `@import` 보다 먼저 와야 합니다.

## 프레임워크별 예시

### Next.js (App Router)

```css title="app/globals.css"
@import '@vapor-ui/core/layers.css';
@import '@vapor-ui/core/styles.css';
```

```tsx title="app/layout.tsx"
import './globals.css';

export default function RootLayout({ children }: { children: React.ReactNode }) {
    return (
        <html lang="ko">
            <body>{children}</body>
        </html>
    );
}
```

### Vite

```css title="src/styles.css"
@import '@vapor-ui/core/layers.css';
@import '@vapor-ui/core/styles.css';
```

```tsx title="src/main.tsx"
import './styles.css';

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

import App from './App';

createRoot(document.getElementById('root')!).render(
    <StrictMode>
        <App />
    </StrictMode>,
);
```

### Storybook

```css title=".storybook/global.css"
@import '@vapor-ui/core/layers.css';
@import '@vapor-ui/core/styles.css';
```

```ts title=".storybook/preview.ts"
import './global.css';
```

## v1 → v2 마이그레이션

v1 에서는 `ThemeProvider` import 가 CSS 를 자동으로 주입했습니다. v2 부터는 자동 주입이 사라지므로, 애플리케이션 CSS 파일에 직접 import 를 추가해야 합니다.

```diff title="app/globals.css"
+ @import '@vapor-ui/core/layers.css';
+ @import '@vapor-ui/core/styles.css';
```

이 변경 이후 컴포넌트가 스타일 없이 렌더링된다면 위 import 가 누락되지 않았는지 확인하세요.
