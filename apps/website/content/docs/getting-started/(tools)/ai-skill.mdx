vapor-ui 플러그인은 AI Agent가 Vapor UI 컴포넌트를 조회하고, Figma 시안을 vapor-ui 코드로 옮기고, 그 결과를 채점하게 돕는 스킬 묶음입니다. 코드를 작성하는 개발자용입니다. Figma에서 시안을 만드는 디자이너용 플러그인은 `vapor-figma`입니다.

**코드를 쓴 에이전트는 채점하지 않습니다.** 구현 맥락을 모르는 검증 에이전트를 새로 띄우고 그 에이전트가 코드를 직접 읽어 판정합니다.

**정답은 Figma Code Connect 템플릿에서 나옵니다.** `@vapor-ui/figma-blueprint`가 시안에 놓인 라이브러리 컴포넌트를 Code Connect 템플릿으로 바꿔 정답 트리를 만듭니다. 같은 시안이면 정답은 항상 같습니다.

**통과하지 못해도 숨기지 않습니다.** 관문을 통과했는지와 상관없이 개선 전후 점수와 남은 실패 항목을 항상 보고합니다.

**검증된 결과라서 믿고 맡길 수 있습니다.** 남은 실패 항목은 파일과 줄 번호까지 보고하므로 어디를 다시 볼지 바로 알 수 있습니다.

## 설치와 업데이트

Claude Code에서는 플러그인으로 설치합니다.

```
/plugin marketplace add goorm-dev/vapor-ui
/plugin install vapor-ui@vapor-ui
```

새 버전은 터미널에서 마켓플레이스 목록을 갱신한 뒤 플러그인을 업데이트해 받습니다. 마켓플레이스만 갱신하면 설치된 플러그인은 바뀌지 않습니다.

```bash
claude plugin marketplace update vapor-ui
claude plugin update vapor-ui@vapor-ui
```

그 밖의 에이전트에서는 Agent Skills CLI로 설치합니다.

```bash
npx skills add goorm-dev/vapor-ui
```

이전에 설치한 `vapor-ui` 스킬은 이제 플러그인 설치 방법만 안내합니다. 플러그인을 설치한 뒤 지워도 됩니다.

채점하려면 앱에 `@vapor-ui/core` 1.7.1, `@vapor-ui/icons` 1.3.3, `@vapor-ui/composites` 0.1.1, `@vapor-ui/figma-blueprint` 0.0.1 이상이 있어야 합니다. `/vapor-ui:setup`이 빠진 패키지와 정답 표가 없는 예전 버전을 찾아 설치합니다.

## 필요한 환경

처음 쓰기 전에 앱 폴더에서 `/vapor-ui:setup`을 한 번 실행합니다. 아래 항목을 확인하고, 빠진 패키지는 고른 것만 설치합니다. 토큰과 Figma MCP는 준비 방법을 안내합니다.

| 필요한 것                   | 최소 버전                                 | 쓰는 스킬                          | 준비 방법                                                                                                           |
| --------------------------- | ----------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Node.js                     | 22.18                                     | `check-components`, `visual-score` | Node 22.18 이상으로 올립니다. 낮은 버전에서는 `figma-blueprint`가 실행되지 않습니다                                 |
| Figma MCP 서버              |                                           | `implement-figma`                  | Figma 공식 MCP 서버를 에이전트에 연결합니다                                                                         |
| `@vapor-ui/figma-blueprint` | 0.0.1                                     | `check-components`, `visual-score` | 앱 패키지에 devDependency로 설치합니다                                                                              |
| Code Connect 템플릿         | core 1.7.1, icons 1.3.3, composites 0.1.1 | `check-components`                 | `@vapor-ui/core`, `@vapor-ui/icons`, `@vapor-ui/composites`를 `figma-blueprint/` 폴더가 들어 있는 버전으로 올립니다 |
| `FIGMA_ACCESS_TOKEN`        |                                           | `check-components`, `visual-score` | 시안 파일을 읽을 수 있는 Figma 개인 토큰을 환경 변수로 둡니다                                                       |
| Playwright                  |                                           | `visual-score`                     | 앱 패키지나 npm 전역에 설치하고 chromium을 받습니다                                                                 |

컴포넌트 패키지는 Code Connect 템플릿을 `figma-blueprint/` 폴더에 담아 배포합니다. figma-blueprint는 설치된 버전의 템플릿으로 정답을 만들기 때문에, 이 폴더가 없는 예전 버전의 컴포넌트는 채점하지 않습니다.

## 스킬

| 스킬               | 하는 일                                                                                         |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| `components`       | 설치된 버전 기준으로 컴포넌트 목록, props, 예제 코드, 아이콘을 조회합니다                       |
| `setup`            | 아래 스킬이 쓰는 환경을 확인하고 빠진 것을 설치합니다. 사용자가 직접 실행합니다                 |
| `implement-figma`  | 채점 없이 Figma 시안 하나를 vapor-ui 코드로만 옮깁니다                                          |
| `check-components` | 관문 1. 시안의 컴포넌트와 props가 코드에 모두 들어갔는지 검증 에이전트가 코드를 읽고 판정합니다 |
| `visual-score`     | 실행 중인 앱 화면을 시안과 비교해 시각 점수를 잽니다                                            |
| `figma-to-code`    | 위 스킬을 순서대로 불러 구현부터 시각 점수까지 한 번에 진행합니다                               |

플러그인으로 설치하면 스킬 이름 앞에 `vapor-ui:`가 붙습니다(`/vapor-ui:figma-to-code`).

스킬 이름 없이 Figma URL과 함께 "이 시안을 vapor-ui로 구현해줘"라고 요청해도 에이전트가 스킬을 고릅니다. 다만 이렇게 요청했을 때 채점하지 않는 `implement-figma`가 불린 기록이 있습니다. 구현과 채점을 함께 원하면 `/vapor-ui:figma-to-code`를 직접 호출합니다.

`figma-to-code`는 구현한 뒤 관문 1을 돌리고, 통과하지 못하면 실패한 항목만 고쳐 최대 2회 다시 채점합니다. 마지막에 시각 점수를 잴 때 앱 URL, 화면을 감싼 요소의 selector, 로그인 상태 파일을 묻습니다. 앱은 직접 띄워 둡니다.

## 점수 읽는 법

`figma-to-code`는 관문을 통과했는지와 상관없이 개선 전후 점수, 남은 실패 항목, 예외 개수를 항상 보여 줍니다.

### 관문 1: 컴포넌트 재현율

`figma-blueprint`가 시안에 놓인 라이브러리 컴포넌트를 Code Connect 템플릿으로 바꿔 정답 트리를 만듭니다. 노드마다 태그, props, Figma node id가 붙고, 라이브러리 컴포넌트끼리만 중첩합니다. 같은 시안이면 정답 트리는 항상 같습니다.

코드를 쓴 에이전트는 채점하지 않습니다. 구현 맥락을 모르는 검증 에이전트를 새로 띄워 정답 트리, 화면의 진입점 컴포넌트, 이번에 쓰거나 고친 파일 목록만 넘깁니다. 검증 에이전트는 진입점에서 로컬 import를 모두 따라가며 코드를 직접 읽고, 노드마다 아래 판정 하나를 내립니다. 문구와 레이아웃은 보지 않습니다.

| 판정         | 뜻                                                               |
| ------------ | ---------------------------------------------------------------- |
| `ok`         | 같은 컴포넌트가 같은 props로, 같은 라이브러리 부모 안에 있습니다 |
| `props`      | 컴포넌트는 있지만 props가 빠졌거나 값이 다릅니다                 |
| `position`   | 컴포넌트와 props는 맞지만 가장 가까운 라이브러리 부모가 다릅니다 |
| `missing`    | 컴포넌트가 없습니다                                              |
| `unscorable` | 코드를 읽을 수 없어 판정하지 못했습니다                          |

`ok` 판정에는 코드 위치(`파일:줄`)가 붙습니다. 집계 스크립트가 그 줄에 컴포넌트가 실제로 있는지 확인하고, 없으면 `ok`로 세지 않습니다. 재현율은 `ok` 노드 수를 판정할 수 있는 노드 수로 나눈 값입니다.

| 결과         | 뜻                                                                                  |
| ------------ | ----------------------------------------------------------------------------------- |
| `pass`       | 모든 노드가 `ok`입니다                                                              |
| `fail`       | `ok`가 아닌 노드가 있습니다                                                         |
| `unscorable` | 판정한 노드는 모두 `ok`지만, 판정하지 못한 노드나 템플릿이 없는 컴포넌트가 있습니다 |

`unscorable`은 설치되지 않았거나 정답 표가 없는 예전 버전의 패키지가 있을 때 생길 수 있습니다. 이때는 `/vapor-ui:setup`으로 패키지를 설치하거나 `figma-blueprint/` 폴더가 들어 있는 버전으로 올린 뒤 다시 채점합니다. 그 뒤에도 남는 항목은 vapor-ui 쪽에 Code Connect가 빠진 경우라 사용자 코드로는 고칠 수 없습니다.

### 시각 점수

시각 점수는 기록용이고 합격선이 없습니다.

| 점수        | 뜻                                                    |
| ----------- | ----------------------------------------------------- |
| Block-Match | 시안과 화면의 글자 줄이 문자열로 짝지어진 면적의 비율 |
| Position    | 짝지어진 글자 줄의 위치가 가까운 정도                 |
| Layout IoU  | 컴포넌트 종류별 영역이 겹치는 정도                    |

시안 쪽 정답은 관문 1과 같은 `figma-blueprint` 정답 트리에서 읽습니다. 글자 줄과 컴포넌트 박스가 그 안에 들어 있습니다.

Block-Match와 Position은 글자를 문자열로 짝짓습니다. 실제 데이터를 그리는 화면은 문구가 시안과 달라 점수가 낮게 나옵니다.

점수와 함께 화면에서 찾지 못한 시안 글자 줄과, 컴포넌트 종류별 IoU와 개수(`0.42 (3→2)`는 시안 3개, 화면 2개)를 보여 줍니다. 무엇이 빠지거나 옮겨졌는지 여기서 찾습니다.

## 예외의 의미

예외는 관문 판정에서 빼고 개수만 보고하는 항목입니다. 실패가 아니지만, 개수가 많으면 컴포넌트로 옮길 수 있는 부분이 숨어 있지 않은지 확인합니다.

**관문 1의 제외.** 컴포넌트가 스스로 그리는 요소라서 코드에 쓸 수 없는 인스턴스입니다.

- `part-draws-icon`: 파트가 그리는 아이콘입니다. `Select.Trigger`의 화살표가 해당합니다.
- `part-draws-itself`: 파트가 조건 없이 그리는 컴포넌트입니다. composites `Dialog`의 닫기 버튼이 해당합니다.
- `inside-self-closing-part`: 자식을 받지 않는 파트 안, 슬롯 밖에 그려진 인스턴스입니다.
