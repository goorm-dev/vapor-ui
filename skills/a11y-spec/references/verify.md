# 증거 수집

`sc-map.md`에서 `컴포넌트` 책임으로 떨어진 SC가 이미 보장되는지 확인한다. **위임은 증거를
요구한다** — 증거는 **관측** 또는 **명세**, 둘뿐이다.

| 기반 구현체       | 방법          | 증거                              |
| ----------------- | ------------- | --------------------------------- |
| base-ui           | **실측**      | 실행 중인 데모를 조작해 얻은 관측 |
| 네이티브 요소     | **명세 확인** | HTML-AAM·MDN·WAI-ARIA 명세        |
| 없음(커스텀 구현) | —             | 전부 `미지원`                     |

기반 구현체는 이 둘이다. react-aria와 Adobe Spectrum은 **구현 참고 자료**다 — 커스텀 구현으로
결정된 컴포넌트에서 "다른 라이브러리는 이렇게 했다"를 출처 각주 한 줄로 적는 데 쓴다. 위임
판정의 증거는 위 표의 둘에서만 나온다.

## 판정 어휘

`report-template.md`가 쓰는 어휘로 **직접** 판정한다.

| 어휘               | 뜻                                 | 함께 적을 것                          |
| ------------------ | ---------------------------------- | ------------------------------------- |
| `지원`             | 실측으로 확인                      | 관측한 값                             |
| `지원 (다른 방식)` | 실측으로 확인. 수단이 규범과 다름  | 무엇으로 대신했나                     |
| `부분`             | 특정 prop 조합에서만 보장          | 어느 조합인가, 어느 조합이 미실측인가 |
| `명세 위임`        | 네이티브 요소의 명세로 확인        | 어느 명세인가                         |
| `미지원`           | 기반 구현체가 안 함 — vapor가 보장 | unstyled라서인지 기능이 없어서인지    |
| `확인 불가`        | 브라우저로 판정 불가               | 사유                                  |

`확인 불가`는 **브라우저로 판정할 수 없을 때** 쓴다. 실측을 아직 안 한 SC는 실측하고 온다.

함께 적을 것이 곧 증거다. 명세명 없는 `명세 위임`, 관측값 없는 `지원`은 `확인 불가`와 같은 값을
갖는다.

`공동(통로)` 구획의 행은 `슬롯 제공`, `소비자` 구획의 행은 `해당 없음`을 갖는다 — 그 두 어휘는
구획이 정하므로 여기서 판정하지 않는다.

## 경로 1 — base-ui 실측

**브라우저가 유일한 증거다.** 소스는 의도를 보여주고 브라우저는 결과를 보여주는데, SC가 걸리는
것은 결과다.

데모: `https://base-ui.com/react/components/<컴포넌트>` (kebab-case)

### 검증 매핑

SC마다 어떤 명령이 증거를 만드는지. **명령이 없는 칸은 `확인 불가`다.**

| SC                        | 검증 방법                                                                                                                                |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 4.1.2 이름·역할·값        | `snapshot -c` — 접근성 트리에 role·이름·상태가 나타나는지. 상태 변경(클릭) 후 재스냅샷해 `expanded`/`checked`/`selected`가 따라 바뀌는지 |
| 1.3.1 정보와 관계         | `eval`로 `aria-labelledby`·`aria-describedby`·`aria-controls`가 실제 id를 가리키는지                                                     |
| 1.3.2 의미 있는 순서      | `snapshot` 전체 — Portal 이동 후에도 트리 순서가 읽기 순서와 맞는지                                                                      |
| 2.1.1 키보드              | `press` 로 위젯 계약의 키 인터랙션 칸대로 눌러보고 매번 `snapshot`으로 상태 변화 확인                                                    |
| 2.1.2 키보드 트랩 없음    | `press Tab` 반복 + `eval`로 `activeElement.closest("[role=dialog]")` 추적. Esc로 탈출되는지                                              |
| 2.4.3 초점 순서           | 열림 시 첫 포커스 위치, 닫힘 후 트리거 복귀를 `eval`로 확인                                                                              |
| 2.4.7 초점 표시           | `press Tab` 후 `screenshot` — 포커스 링이 눈에 보이는지                                                                                  |
| 2.4.11 초점 가려지지 않음 | 포커스 요소와 오버레이의 `get box`를 비교해 겹침 계산                                                                                    |
| 2.5.8 타깃 크기           | `get box @eN` — width·height ≥ 24                                                                                                        |
| 1.4.3 / 1.4.11 대비       | `get styles @eN`로 색을 뽑고 대비비 계산                                                                                                 |
| 1.4.13 호버 콘텐츠        | `hover` → 팝업 위로 포인터 이동 가능한지, Esc로 닫히는지, 호버 유지 중 안 닫히는지 3건                                                   |
| 4.1.3 상태 메시지         | `snapshot`에 `status`/`alert` role이 있는지 + 내용 변경 시 발화되는지                                                                    |
| 전 항목 자동 훑기         | `agent-browser a11y --json` (axe-core). **보조 신호다** — axe가 통과해도 준수가 아니고, axe 규칙은 SC와 1:1이 아니다                     |

### 실전 함정 (실측에서 걸린 것)

1. **ref는 페이지가 바뀌는 즉시 무효다.** Dialog를 열거나 Esc로 닫았으면 **재스냅샷 후** 새
   `@eN`을 쓴다. 이전 ref는 엉뚱한 요소를 잡는다. 그래서 상태 전이 SC(4.1.2·2.4.3)는 조작한
   그 자리에서 판정한다 — 0단계에 미리 뜬 스냅샷은 조작 후 상태를 담지 못한다.
2. **`eval`은 스코프가 호출 간에 유지된다.** `const a = ...`를 두 번 실행하면
   `Identifier 'a' has already been declared`로 죽는다. IIFE로 감싼다:
   `(()=>{ const a=...; return ... })()`
3. **`get box`·`get styles`다.** `box`·`styles` 단독은 없다.
4. **role 검증에는 `snapshot -c`(전체)를 쓴다.** `snapshot -i`는 인터랙티브 요소만 보여준다.

### 실측 예 — Dialog (2026-08-14)

```bash
agent-browser open https://base-ui.com/react/components/dialog
agent-browser snapshot -i -c -s "main"     # 트리거 ref 확보
agent-browser click @eN
agent-browser snapshot -c                  # role/이름/배경 소멸 확인
agent-browser eval '(()=>{const d=document.querySelector("[role=dialog]");return {ariaModal:d.ariaModal,labelledby:d.getAttribute("aria-labelledby")}})()'
```

판정 근거는 **수단이 아니라 결과**다. 위 Dialog는 `role="dialog"` +
`aria-labelledby`/`describedby`로 4.1.2를 충족하고, 배경이 트리에서 사라져 1.3.2를 충족한다 —
단 수단은 `aria-modal`도 네이티브 `<dialog>`도 아닌 배경 `aria-hidden`이다(`ariaModal: null`).
`지원 (다른 방식)`으로 적고 그 수단을 밝힌다. **이 사실까지 적어야 판정이 방어된다.**

⚠️ **prop 조합별로 따로 실측한다.** 위 결과는 `modal` 기본값이다. Dialog 실측(2026-08-20)에서
`modal="trap-focus"`가 기본값과 갈리는 지점은 `body` 스크롤 락 하나뿐이었다 — 배포 소스의
조건식(`modal === true`)을 읽고 "백드롭이 꺼진다"고 추론했던 이전 판은 브라우저에서 반증됐다.
**분기 판정은 소스가 아니라 브라우저로 확정한다.** 0단계 정찰 4번의 prop 목록이 이 실측 계획의
입력이다.

## 경로 2 — 네이티브 요소 명세 확인

조작할 데모가 없다. vapor 코드가 아직 없기 때문이다. `<nav>`가 `role=navigation`을 준다는 것은
관측 대상이 아니라 **명세**이고, 명세는 브라우저 동작을 규정하므로 증거로 데모 관측보다 위다.

**명세를 읽어서 판정한다.** 최소 마크업을 지어내 재면 대상이 vapor 마크업이 아니라 방금 지어낸
마크업이라 증거가 순환한다.

| 확인할 것                  | 명세                                                                |
| -------------------------- | ------------------------------------------------------------------- |
| 요소 → role 매핑           | HTML-AAM `https://www.w3.org/TR/html-aam-1.0/`                      |
| role의 필수 속성·허용 자식 | MDN ARIA role 문서 / WAI-ARIA `https://www.w3.org/TR/wai-aria-1.2/` |
| 네이티브 키보드 동작       | HTML 표준의 해당 요소 절                                            |
| 접근 가능 이름 계산        | AccName `https://www.w3.org/TR/accname-1.2/`                        |

**시각 축**은 네이티브 요소도 주지 않는다. `<hr>`도 3:1 대비를 보장하지 않는다 — "네이티브
가능"은 위임처가 브라우저라는 뜻이고, SC는 그대로 남는다. 시각 축 목록은 `sc-map.md`가 소유한다.
