# Button 접근성 명세

**규범**: WCAG 2.2 Level A/AA + KWCAG 2.2
**실측**: base-ui `Button` 공식 데모 (<https://base-ui.com/react/components/button>), 기본 데모(`<Button>Submit</Button>`) + 로딩 데모(`disabled={loading} focusableWhenDisabled`), Chromium 1280×800 / 320×800, 2026-08-18
**적용 SC**: 25건 (WCAG 22 + KWCAG 고유 3)

이 문서는 판정이 아니라 **설계 입력**이다. vapor Button은 이미 있으나, 이 리포트는 구현을 채점하지 않고 지켜야 할 것만 나열한다.

---

## 1. 성질

| 태그             | 근거                                                          |
| ---------------- | ------------------------------------------------------------- |
| `interactive`    | 탭으로 도달하는 `<button>` — 포커스와 활성화를 받는다         |
| `pointer-target` | 포인터로 누르는 히트 영역을 갖는다                            |
| `text`           | children으로 레이블 텍스트를 직접 렌더한다                    |
| `visible-label`  | 화면에 보이는 텍스트가 곧 접근 가능한 이름이다                |
| `icon`           | 아이콘 children을 받는다 — 아이콘 전용(텍스트 0) 사용도 가능  |
| `ui-boundary`    | `variant`(solid/outline/ghost)가 테두리·배경으로 경계를 그린다 |
| `state-visual`   | hover·pressed·disabled를 시각 신호로 구분한다                 |

**붙지 않은 것**: `form-control`(제출을 트리거할 뿐 값을 담지 않는다 — `validatable` 연쇄를 차단한다), `composite`(내부 항목 관리·roving tabindex 없음, 탭 정지점이 곧 자기 자신), `overlay`·`transient`·`modal`(레이어로 뜨지 않는다), `auto-motion`(vapor Button에 loading 스피너 prop이 없다 — 생기면 2.2.2·2.3.1이 되살아난다), `gesture`(드래그·스와이프 없음), `char-shortcut`(단일 문자 키 바인딩 없음), `status-message`(자기 상태를 AT에 방송하지 않는다), `link`(base-ui가 `<a>` 렌더를 명시적으로 금지한다), `text-input`·`table`·`media`·`device-motion`(구조 자체가 없다).

### 조건부 위임

| SC    | 제목         | Lv  | 조건                                                                                                                                                                                                        |
| ----- | ------------ | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4.1.2 | 이름·역할·값 | A   | `focusableWhenDisabled` 사용 시 — 로딩 데모에서 Enter 후 `{ad:"true", dis:false, ti:"0", focused:true, txt:"Submitting…"}` 관측. 비활성 표현이 네이티브 `disabled`가 아니라 `aria-disabled="true"`로 나가고 tabindex 0과 포커스가 유지된다 |
| 2.4.3 | 초점 순서    | A   | 같은 조합 — 비활성 전이에서 포커스가 버튼에 남는다(`focused:true`). **기본값(`focusableWhenDisabled={false}`)에서는 네이티브 `disabled`가 붙어 포커스를 잃을 것으로 보이나 미실측**                          |

> ⚠️ **`nativeButton={false}` + `render` 조합은 실측하지 않았다.** 이 조합에서는 base-ui가 `<button>` 대신 임의 태그에 `role="button"`과 키 핸들러를 얹는다 — 즉 위 표의 "네이티브라서 공짜"라는 근거가 통째로 사라지고, Space 활성화·`type="button"` 기본 동작·폼 제출 의미가 전부 base-ui 구현에 걸린다. **vapor Button이 `render`를 열어둔 채 출하한다면 그 조합으로 2.1.1·4.1.2를 다시 재야 한다.**

## 6. 설계 결정으로 올릴 것

1. **아이콘 전용 Button의 이름을 강제할 것인가** — 1.1.1·2.5.3이 걸린다. `aria-label` 없이 아이콘만 넣으면 이름이 빈다. 타입으로 강제(아이콘 전용 variant에서 `aria-label` 필수)하면 통합자가 못 어기지만 API가 갈라지고, 문서로만 두면 위반이 조용히 새어 나간다.
2. **아이콘 전용 Button의 최소 크기** — 2.5.8은 24×24를 요구하는데 데모 측정값의 폭 72px은 레이블 길이 덕이다. `size` 스케일의 최소값이 24를 밑돌면 아이콘 전용에서 바로 깨진다. `size`별 실측이 선행돼야 한다.
3. **`render`/`nativeButton={false}`를 공개할 것인가** — 열면 2.1.1·4.1.2의 근거가 "네이티브"에서 "base-ui 구현"으로 갈아탄다. 열 거면 그 조합의 실측이 출하 조건이다.
4. **`disabled`의 기본 표현** — 네이티브 `disabled`(탭 순서에서 제거)와 `focusableWhenDisabled`(=`aria-disabled`, 포커스 유지) 중 무엇을 기본으로 할지. 비활성 버튼에 포커스가 닿아야 이유를 읽을 수 있고, 닿지 않으면 탭 순서가 깨끗하다.
5. **로딩 중 접근 가능한 이름 변경** — 실측에서 이름이 `"Submit"` → `"Submitting…"`으로 바뀌었다. APG는 토글 버튼의 레이블 유지를 권하고, 이름이 바뀌면 2.5.3(이름 속의 레이블)이 흔들린다. 상태를 이름에 실을지, 별도 상태 메시지로 뺄지 결정해야 한다(후자면 `status-message` 성질이 붙고 4.1.3이 되살아난다).
6. **ghost/naked variant의 경계** — KWCAG 5.4.4는 테두리 없는 컨트롤을 문제 삼는다. 테두리 없는 variant에서 무엇으로 경계를 대신할지(배경 대비·간격) 규정이 필요하다.

## 참고 (근거 아님)

- APG Button 패턴: <https://www.w3.org/WAI/ARIA/apg/patterns/button/> — 키보드 인터랙션 표(Space·Enter 활성화)와 `aria-pressed`·`aria-disabled` 대조에 사용. **정보성 문서라 준수 근거로 인용하지 않는다**
- axe-core 4.12.1 자동 감사 결과 `violations: 0`, `incomplete: 1`(color-contrast 31 노드, 대부분 "배경색을 판정할 수 없음") — 보조 신호일 뿐. axe 규칙은 SC와 1:1이 아니며 통과가 준수를 뜻하지 않는다
