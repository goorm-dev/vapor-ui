# ADR-0003: color-generator는 기준 스크립트를 포팅하고 색조를 세 앵커 곡선으로 만듭니다

- **상태**: Accepted
- **날짜**: 2026-11-20
- **관련**: Notion "Foundation 컬러 팔레트 접근성 개선 (2)", "(3)", `generate_palette.py`

## Context

`@vapor-ui/color-generator`는 `@adobe/leonardo-contrast-colors`로 팔레트를 만들었습니다. 이 방식에는 세 가지 문제가 있었습니다.

- 목표 명암비가 light와 dark 공통 표 하나였습니다.
- dark 팔레트는 같은 배경의 lightness만 바꿔 만들었습니다.
- 브랜드 컬러는 deltaE가 가장 가까운 칸에 hex를 그대로 넣었습니다. 그 칸의 명암비는 다시 검사하지 않았습니다.

그 결과 일부 칸이 목표 명암비에 미치지 못했고, dark 모드에서는 접근성이 깨졌습니다.

디자인 팀은 명암비, 채도, 색조 규칙을 Python 기준 스크립트로 정했습니다. 이 스크립트의 출력이 팔레트의 정답입니다. 공식 Leonardo는 CAM02 경로의 색을 그대로 씁니다. 반면 기준 스크립트는 OKLCH 보간에서 색조만 가져옵니다. 그래서 Leonardo를 유지하면서 후처리를 덧대는 방식으로는 같은 결과를 낼 수 없습니다.

## Decision

Leonardo와 culori 의존성을 제거합니다. 기준 스크립트의 알고리즘을 TypeScript로 1:1 포팅합니다. 포팅 대상은 다음과 같습니다.

- 색 변환: Ottosson 행렬, WCAG 2.x 휘도
- 색조 곡선: 색마다 light 050·600·900 세 칸의 hue(앵커)만 정합니다. 나머지 칸은 세 앵커를 monotone cubic(Fritsch–Carlson)으로 이어 읽습니다. 가로축은 각 칸의 light 목표 명암비가 흰 배경에서 주는 명도로, 모든 색이 같은 축을 씁니다. monotone이라 곡선은 앵커 범위를 벗어나지 않습니다.
- 명도 이분 탐색
- 채도 규칙: light 500–900은 차례로, 이웃 평균의 1.1배(900은 800의 1.1배)를 넘는 채도를 그 상한에서 다시 풉니다. 한 칸만 튀는 채도를 막습니다.
- 팔레트 검사: `chroma` 검사도 같은 상한을 적용한 값을 기준으로 삼습니다.

디자이너가 손으로 고치던 진한 warm 색조(red 900, orange 600·900, yellow 900)는 기본 앵커값으로 넣습니다. basic·brand HEX는 500 hue가 가장 가까운 기본 색의 세 앵커를 hue 차이만큼 평행 이동해 씁니다. 사용자는 `hueAnchors`로 앵커를, `hueOverrides`로 칸 하나를 바꿉니다. 적용 순서는 앵커 → 곡선 → `hueOverrides`입니다.

기준 스크립트의 `palette.json`을 golden fixture로 둡니다. 기본 입력에 대한 생성 결과는 이 fixture와 HEX가 완전히 같아야 합니다.

## Consequences

- 규칙이 바뀌면 Python 스크립트를 먼저 고칩니다. 그다음 TS 포팅과 fixture를 갱신합니다. 두 구현은 fixture 테스트로 동기화합니다.
- 연산 순서와 반올림 위치가 결과 HEX에 영향을 줍니다. 그래서 포팅할 때 "더 깔끔한" 수식으로 바꾸면 안 됩니다.
- 외부 색 라이브러리 의존성이 없어집니다. 대신 색 변환 코드를 직접 유지보수해야 합니다.
- 디자이너 보정값이 기본값이 되어, 기본 팔레트 HEX가 바뀝니다(light 69칸, dark 83칸). 디자이너는 진한 warm 색조를 더 손으로 고치지 않아도 됩니다. 새 보정은 앵커 표나 `hueAnchors`로 넣습니다.
- 앵커 세 개만 정하므로 곡선 모양(050–600, 600–900 사이)은 직접 고를 수 없습니다. 한 칸만 바꿀 때는 `hueOverrides`를 씁니다.
- 채도 상한은 light에서만 적용합니다. 상한에 걸린 칸(예: red 500, violet 600, cobalt 500·800)은 최대 채도보다 조금 흐려집니다. dark는 상한을 거친 light 곡선에서 유도합니다.
- 고정된 brand 칸은 사용자 입력이라 상한을 받지 않습니다. 채도가 낮은 brand HEX는 이웃 칸이 상대적으로 튀어 보일 수 있습니다.
- 포팅 전 기준 스크립트의 `gamut_chroma` 결함을 먼저 고칩니다. 파랑 계열에서 sRGB 경계가 C 방향으로 단조롭지 않아(R 채널이 0 근처에서 ±0.0002 진동) 이분 탐색이 낮은 경계에서 멈춥니다. 위에서부터 훑는 방식으로 바꾸면 cobalt light-800 한 칸만 바뀌고 Figma 값과 일치합니다.
